The request pipeline

docs: request lifecycle

Almost every Nest question is "which stage does this belong in?". A request passes the same stages in the same order every time.

  1. Middlewareraw req/res, runs first
  2. Guardsallowed in? yes/no
  3. Interceptorsbefore handler
  4. Pipesvalidate, transform
  5. Handlercontroller method, then service
  6. Interceptorsafter handler
  7. Responsesent to client

An exception thrown at any stage skips the rest and goes to Exception filters, which build the error response. Shaded stages are the ones you write most.

Modules and controllers

docs: modules

Module: one per feature

A module is a box. Nothing leaves it unless it is exported, and nothing enters unless it is imported.

@Module({
  imports: [UsersModule],         // modules whose exports I need
  controllers: [TicketsController],
  providers: [TicketsService],
  exports: [TicketsService],      // what other modules may inject
})
export class TicketsModule {}

@Global() skips the import step. Keep it for config and logging only.

Controller: thin HTTP layer

@Controller('tickets')
export class TicketsController {
  constructor(private readonly tickets: TicketsService) {}

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.tickets.findOne(id);
  }

  @Patch(':id')
  @HttpCode(200)
  update(@Param('id', ParseIntPipe) id: number, @Body() dto: UpdateTicketDto) {
    return this.tickets.update(id, dto);
  }
}

Read the request, call the service, return. No business rules here.

Handler decorators you will use

DecoratorGives you
@Get() @Post() @Put() @Patch() @Delete()HTTP method and path. PATCH for partial update, PUT for full replace.
@Param('id')URL segment. Always a string, so add ParseIntPipe or ParseUUIDPipe.
@Query()Query string. Use a DTO class to validate it.
@Body()Request body, validated against the DTO type.
@Headers('x-api-key')One request header.
@HttpCode(204)Override the status code. POST defaults to 201, others to 200.
@Header('Cache-Control', 'no-store')Set a response header.
@Redirect(url, 302)Redirect response.
@Req() @Res()Raw Express/adapter objects. Avoid. @Res() switches off interceptors and automatic responses.

Route order matters

Nest matches in declaration order. Put static routes before parameter routes.

@Get('stats')   // declare first
stats() {}

@Get(':id')     // would swallow "stats" if it came first
findOne() {}

Global prefix: app.setGlobalPrefix('api') (done in main.ts). API versions: app.enableVersioning(), then @Controller({ path: 'tickets', version: '1' }).

Providers and dependency injection

docs: custom providers

A provider is any class Nest can build and hand to others. You ask for it in a constructor, and Nest supplies it. Never write new TicketsService().

Service

@Injectable()
export class TicketsService {
  // Nest sees the parameter type and injects it
  constructor(private readonly mailer: MailerService) {}
}

Must be listed in a module's providers. If another module needs it, export it and import that module.

Custom providers

providers: [
  // fixed value, injected by string token
  { provide: 'MAIL_FROM', useValue: 'help@acme.dev' },

  // swap an implementation (great for tests)
  { provide: Mailer, useClass: SmtpMailer },

  // build with other providers
  {
    provide: 'DB',
    useFactory: (config: ConfigService) => connect(config.get('DB_URL')),
    inject: [ConfigService],
  },

  // second name for an existing provider
  { provide: 'LegacyMailer', useExisting: Mailer },
]

// consuming a token
constructor(@Inject('MAIL_FROM') private readonly from: string) {}

Scopes

  • DEFAULT: one shared instance for the whole app. Use this almost always.
  • REQUEST: new instance per request. Everything that depends on it becomes request-scoped too, which costs speed.
  • TRANSIENT: new instance per consumer.
@Injectable({ scope: Scope.REQUEST })

For per-request data such as the current user, prefer a param decorator or AsyncLocalStorage over request scope.

Lifecycle hooks

@Injectable()
export class PrismaService implements OnModuleInit, OnApplicationShutdown {
  async onModuleInit() { /* connect */ }
  async onApplicationShutdown() { /* disconnect */ }
}

// main.ts: needed for shutdown hooks to fire on SIGTERM
app.enableShutdownHooks();

Circular dependency

Two providers needing each other is a design smell. First try moving the shared part into a third service. Last resort: @Inject(forwardRef(() => OtherService)) on both sides.

Dynamic modules

Modules that take options: ConfigModule.forRoot({...}). The forRootAsync variant waits for config before building. You will use these long before you write one.

Validation and pipes

docs: validation

Never trust a request body. Describe the allowed shape once, as a DTO, and let a pipe enforce it before your handler runs.

DTO with class-validator

export class CreateTicketDto {
  @IsString() @IsNotEmpty()
  subject: string;

  @IsIn(['low', 'medium', 'high'])
  priority: 'low' | 'medium' | 'high';

  @IsOptional() @IsString()
  description?: string;
}

Only properties with a decorator survive whitelist. An undecorated field is silently stripped.

Switch it on once

app.useGlobalPipes(new ValidationPipe({
  whitelist: true,              // drop unknown properties
  forbidNonWhitelisted: true,   // ...and answer 400 instead of ignoring
  transform: true,              // "5" in query becomes 5, plain object becomes DTO
}));

That is why PATCH {"status":"closed"} returns 400 in this project.

Schema libraries (new)

Zod, Valibot, ArkType or any Standard Schema library works with no classes or decorators.

const createTicketSchema = z.object({
  subject: z.string().min(1),
  priority: z.enum(['low', 'medium', 'high']),
});

@Post()
create(@Body({ schema: createTicketSchema }) dto: z.infer<typeof createTicketSchema>) {}

Handled by StandardSchemaValidationPipe. Pick one style per project and do not mix them.

Derive DTOs, do not copy them

// package: @nestjs/mapped-types
export class UpdateTicketDto extends PartialType(CreateTicketDto) {}

PickType(CreateTicketDto, ['subject'])
OmitType(CreateTicketDto, ['priority'])

One rule, one home. Hand-writing the update DTO also works for three fields, as in this project.

Exceptions and filters

docs: exception filters

Throw, do not return errors

const ticket = this.tickets.find((t) => t.id === id);
if (!ticket) throw new NotFoundException(`Ticket ${id} not found`);
BadRequestException400
UnauthorizedException401 (not logged in)
ForbiddenException403 (logged in, not allowed)
NotFoundException404
ConflictException409 (duplicate)
UnprocessableEntityException422
InternalServerErrorException500

One error shape for the API

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name);

  catch(exception: unknown, host: ArgumentsHost) {
    const response = host.switchToHttp().getResponse();
    const status =
      exception instanceof HttpException ? exception.getStatus() : 500;

    // Unknown errors are logged but never leaked to the client
    if (status === 500) this.logger.error(exception);

    response.status(status).json({
      statusCode: status,
      message: exception instanceof HttpException
        ? exception.message
        : 'Internal server error',
    });
  }
}

// register through DI so the filter can inject things
providers: [{ provide: APP_FILTER, useClass: AllExceptionsFilter }]

Map database errors before they reach the client

Services should speak HTTP-friendly errors, not driver errors. Catch the known codes (for example Prisma's unique-constraint error) and rethrow a ConflictException. Let everything unknown fall through to the filter as a 500.

Guards and authentication

docs: guards

Guard plus metadata

Tag routes with SetMetadata, read the tag in a guard with Reflector.

export const Roles = (...roles: string[]) => SetMetadata('roles', roles);

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const roles = this.reflector.getAllAndOverride<string[]>('roles', [
      context.getHandler(),   // method decorator wins over class decorator
      context.getClass(),
    ]);
    if (!roles) return true;
    const { user } = context.switchToHttp().getRequest();
    return roles.includes(user?.role);
  }
}

@Roles('admin')
@Delete(':id')
remove() {}

Protect everything, opt out per route

providers: [{ provide: APP_GUARD, useClass: AuthGuard }]

// then mark open routes
export const Public = () => SetMetadata('isPublic', true);

Safer than remembering to add @UseGuards() on every new route.

Security checklist and the built-in help

  • Sign-in: @nestjs/authentication. Passport recipe still works if you prefer it.
  • Permissions: @nestjs/authorization or your own role guard.
  • Passwords: hash with argon2 or bcrypt. Never store or log the plain value.
  • Rate limiting: @nestjs/throttler on login and public POST routes.
  • Headers and CORS: helmet, and app.enableCors({ origin: [...] }) with an explicit list.
  • Secrets: only from environment variables, never committed.

Interceptors

docs: interceptors

Wrap the handler

@Injectable()
export class TimingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('HTTP');

  intercept(context: ExecutionContext, next: CallHandler) {
    const started = Date.now();
    return next.handle().pipe(
      tap(() => this.logger.log(`done in ${Date.now() - started}ms`)),
    );
  }
}

Code before next.handle() runs before the handler. Operators in pipe() run after it.

Good uses

  • Request timing and structured logging.
  • Response envelope: map((data) => ({ data })).
  • Timeouts: timeout(5000) from rxjs.
  • Caching: use CacheInterceptor from @nestjs/cache-manager.
  • Hiding fields: ClassSerializerInterceptor.

Register globally with APP_INTERCEPTOR, or per controller with @UseInterceptors().

Custom decorators

docs: custom decorators

Param decorator

export const CurrentUser = createParamDecorator(
  (_data: unknown, context: ExecutionContext) =>
    context.switchToHttp().getRequest().user,
);

@Get('me')
me(@CurrentUser() user: AuthUser) {
  return user;
}

Compose decorators

export const AdminOnly = () =>
  applyDecorators(Roles('admin'), UseGuards(RolesGuard));

Fewer lines on every controller, and the combination lives in one place.

Layering

Controller   HTTP in/out, DTOs
   |
Service      business rules, transactions
   |
Repository   the only place that touches the DB
   |
Database

Start with the service talking to the data client directly. Add a repository class when queries get big or you want to swap storage in tests.

Never return raw entities

A database row often has fields the client must not see (password hash, internal flags). Return a response shape on purpose.

// option 1: explicit mapping (clearest)
return { id: user.id, email: user.email };

// option 2: hide fields on the class
class UserEntity {
  @Exclude() passwordHash: string;
}
// plus ClassSerializerInterceptor

Habits that save you later

  • Paginate every list endpoint from day one (page and limit with caps).
  • Use a transaction for any multi-step write.
  • Index foreign keys and the fields you filter on.
  • Watch for N+1: loading a relation inside a loop.
  • Database id types and DTO types are separate things. Do not reuse one for the other.

Testing

docs: testing

Unit test a service

const moduleRef = await Test.createTestingModule({
  providers: [
    TicketsService,
    { provide: MailerService, useValue: { send: vi.fn() } },  // vi.fn, not jest.fn
  ],
}).compile();

const service = moduleRef.get(TicketsService);

it('throws 404 for an unknown id', () => {
  expect(() => service.findOne(999)).toThrow(NotFoundException);
});

End-to-end test

const app = moduleRef.createNestApplication();
app.setGlobalPrefix('api');          // same setup as main.ts
app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true }));
await app.init();

await request(app.getHttpServer())
  .patch('/api/tickets/1')
  .send({ status: 'closed' })
  .expect(400);

Common trap: an e2e app without the prefix and pipes from main.ts behaves differently from the real one. Move that setup into one configureApp(app) function and call it from both.

What to cover

  • Services: unit tests with mocked dependencies. This is where the rules live.
  • Routes: a few e2e tests per feature: happy path, validation failure (400), missing resource (404), no permission (401 or 403).
  • Guards, pipes, filters: small unit tests when they contain logic of their own.

Beyond REST

docs: microservices

Nest is not only for JSON APIs. The same modules, providers, guards and pipes work across transports.

WebSockets

A @WebSocketGateway() class with @SubscribeMessage('event') handlers. Guards, pipes and filters apply to messages too. Use it for live ticket updates or chat.

Server-Sent Events

@Sse('stream') returning an rxjs Observable. One-way push is simpler than WebSockets for notifications.

Microservices

Redis, NATS, MQTT, RabbitMQ, Kafka, gRPC. Handlers use @MessagePattern() (request/response) and @EventPattern() (fire and forget). Only split services when you have a reason; a modular monolith comes first.

Queues

Slow or retryable work (email, reports) goes to a BullMQ queue and a @Processor() class. The request returns fast and the job runs in the background.

Scheduled tasks

@Cron('0 * * * *') from @nestjs/schedule. With several instances, guard it with @nestjs/locks so it runs once.

Also in the box

GraphQL (code-first or schema-first), OpenAPI/Swagger docs with the CLI plugin, CQRS recipe, standalone apps (scripts and CLIs using DI without HTTP), hybrid apps (HTTP plus a microservice transport).

Good practice

  • DoOne module per feature. Keep controllers thin and services free of HTTP types.
  • DoGive every input a DTO or schema, and turn on whitelist and forbidNonWhitelisted.
  • DoRegister global guards, pipes, filters and interceptors with APP_* providers so they can use DI.
  • DoThrow built-in HTTP exceptions from services and format them in one filter.
  • DoValidate env at startup and read it through ConfigService.
  • DoEnable shutdown hooks and add a health endpoint before the first deploy.
  • DoWrite unit tests for service rules and e2e tests for validation and auth failures.
  • Avoidnew SomeService() anywhere. Inject it.
  • AvoidBusiness logic in controllers, or @Req()/@Res() unless you must stream.
  • AvoidReturning database entities straight to the client.
  • Avoid@Global() and forwardRef as shortcuts. They hide design problems.
  • AvoidRequest-scoped providers by default. They slow every dependent class.
  • AvoidUnpaginated list endpoints and console.log in app code.
  • AvoidAdding a library before checking the first-party package list above.
